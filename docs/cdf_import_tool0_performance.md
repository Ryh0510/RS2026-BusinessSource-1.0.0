# 2026-10-08 CDF 格式、间距与查询提速

## 导出

CDF 的 MOD 按桌面 MainModule.mod 固定为 MODULE MainModule / CONST robtarget / PROC main / MoveL v50 z10 tool0\WObj:=wobj0。位置为当前实际 TCP 的世界坐标毫米值，四元数 wxyz，位置6位、姿态9位；不输出自定义工具或负载。保留先前按用户指定改成 tool0 时的坐标语义：tool0 将这些数字解释为法兰目标，不自动换算法兰补偿轨迹。详细说明见 cdf_rapid_export.md。

## 12 列输入

每行：`x y z qw qx qy qz speed acceleration time type standoff`。

- 位置 mm→m，速度 mm/s→m/s，姿态按 wxyz 归一化，时间保持原秒值（包括0和重复时间）。
- 每行必须12个有限数值、非零四元数、非负速度/时间/喷距、整数点类型；倒退时间和坏行报行号，整份拒绝，不发布半份轨迹。
- 加速度、点类型和喷距已识别，但当前预编译 TimedCartesianPoint 只提供 pose/time/linearSpeed/angularSpeed；后三种工艺信息不会冒充姿态或时间，也不自动修改喷枪或控制执行。本轮没有改变 SDK 或增加项目持久化字段。
- 修复通用矩阵解析把12列截为4列的问题；原4×4矩阵、8列位姿、六轴关节表与显式12轴关节表保持兼容。

## 安全距离与等价范围

2026-10-08 后续按用户要求恢复：领域默认与CDF页面均为0.01m（10mm），UI步长0.001m。APF与CDF/QP读取同一安全距离；不再用隐藏的5mm下限覆盖显式参数。最终间距合格与无碰撞分开报告，设置10mm不等于所有输入一定达到10mm。下文0.5mm对照为此前的片段试验记录。

安全距离配置会影响搜索轨迹。此前提速等价性仅覆盖相同输入、场景及0.5mm参数的已无碰撞片段；没有覆盖完整234点Top-1流程。失败复核发现0.001rad候选验收与0.00025rad最终验收不一致，现将所有阶段候选验收统一到最终精度。该正确性修复会改变候选接受，不宣称输出与旧版本逐字节相同。

## 提速实现

- 单次优化复用碰撞查询工作线程；每线程独占原来的独立场景，每批次等待所有任务完成后才进行下一步。异常会在所有任务结束后传回调用方，析构先停线程再释放场景。
- 平滑候选的间距验收为全点谓词。一点失败即足以拒绝该候选，停止还未开始的距离查询；已开始的任务等待完成。通过的候选仍检查所有点，之后仍进行原运动碰撞检查。
- 保留精确 double 缓存键、QP轮数、采样、容差、浮点求解顺序与最终不使用缓存的高密度验收。全值查询及质量报告不走提前拒绝路径。

## 当前版本GPU接入核对

- 当前 CollisionTypes.h 只有 Default/Fcl/Coal，没有现成GPU后端；环境PATH未找到nvcc，标准CUDA Toolkit目录未发现安装。
- 升级后的低层 CollisionWorld 已有 unique_ptr<ICollisionBackend> 自定义后端构造函数（不能沿用旧版本“完全不能注入后端”的说法）。但正式APF使用的 ProjectCollisionRuntime 内部 CollisionScene 只有默认构造，world_ 私有，没有公开工厂/后端注入入口。
- 仅把6维APF势场加减乘除搬GPU，仍需等待CPU的距离与碰撞；一轮的12个差分探针/前瞻候选可批量并行，路径迭代和站点选择仍有前后依赖。实质加速需碰撞/距离批量GPU实现及运行时扩展点。
