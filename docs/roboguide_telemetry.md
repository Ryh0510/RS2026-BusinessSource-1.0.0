# ROBOGUIDE Classic 通用只读通信

在 ROBOGUIDE Classic 打开工作站并等待虚拟控制器启动，然后进入本软件的“数字孪生”工作台，点击“启动通信”。通过本机已安装的 FANUC Robot Neighborhood / Robot Server COM 接口发现运行中的虚拟控制器，不要求指定工程目录、机器人型号、IP 或端口。

- 一个可用控制器：自动连接。
- 多个可用控制器：先“刷新工作站”，从列表选择控制器，再启动。列表包含完整身份路径，便于区分同名机器人。
- 没有可用控制器：提示打开工作站，不会自行启动其他注册工作站。
- 默认运动组 1、请求周期 20 ms；可选其他运动组和 10–1000 ms 周期。实际周期取决于控制器刷新、COM 调用及系统调度，不保证硬实时。
- “停止通信”异步停止采集并关闭记录文件。切换工作台后继续采集；退出软件后释放通信资源。

采集只读取当前关节数据，不改变机器人、程序或寄存器。显示保留 FANUC 原始关节值及完整圈数；转动轴为度，外轴保持控制器原单位。原始数据不因场景模型的关节约定而改变；只有显式打开场景跟随时才通过下述模型映射更新场景。

CSV 默认保存到用户文档目录 RS2026/Telemetry；每次自动生成新文件，也可选择保存位置。已有文件不会覆盖。采集故障后停止产生新样本，界面保留并标记最后一帧。再次启动会重新发现控制器。

| CSV 列 | 含义 |
| --- | --- |
| sequence | 从 1 开始的有效样本序号 |
| received_utc_unix_ns | 主机接收结果时的 UTC Unix 纳秒时间；不是控制器内部时间 |
| elapsed_ns | 当前连接开始后的主机单调时钟，适合计算实际采样间隔 |
| read_latency_ns | 本次读取耗时 |
| J1…Jn | 本运动组的原始关节/外轴值，按实际数量生成 |

文件头记录控制器身份、运动组、请求周期和单位语义。UTC 时钟可能被系统校时；分析间隔应使用 elapsed_ns。所有通信和文件记录由无 Qt、无渲染依赖的 C++ Session 在后台线程中完成，界面只显示有界的最新快照。

本机依赖是已安装并注册的 FANUC Robot Neighborhood / Robot Server；不是在未安装 FANUC 组件的电脑上直接连接任意软件。生产代码没有绑定联调工作站路径。


## 实时末端 TCP 位姿

启动通信后，数据区可切换“关节”和“末端 TCP 位姿”两页。TCP 页显示 X/Y/Z（mm）、W/P/R（deg）及本次读取的 UF/UT。XYZ/WPR 直接读取 FANUC Robot Server 当前位姿，不使用本工程机器人模型做正解。

坐标统一采用 FANUC 控制器 WORLD（UF0），末端为当前激活工具 UT 的 TCP；它不是 ROBOGUIDE 工作站全局坐标。与 ROBOGUIDE 示教器比较时，应使用 WORLD 显示及相同运动组、相同 UT。示教器 USER 显示可能有 UFRAME 偏移。WPR 采用 FANUC 约定，旋转矩阵为 Rz(R) * Ry(P) * Rx(W)。

同次当前位姿刷新后，先保留 WORLD 笛卡尔表示，再读取关节表示，使用同一条采样时间记录。Robot Server 的 Formats(frJoint) 会改变缓存表示，因此每个采样重新请求 WORLD，避免下一次把 USER 坐标当作 WORLD。

CSV 在原时间与关节列后追加：tcp_valid、tcp_x_mm、tcp_y_mm、tcp_z_mm、tcp_w_deg、tcp_p_deg、tcp_r_deg、tcp_uf、tcp_ut、tcp_status。文件头也写明坐标和单位。TCP 不支持、数值无效或坐标系身份无法确认时，界面清空位姿表，CSV 记录有效性 0 与 nan；可用的关节采集继续，绝不沿用旧位姿冒充新值。连接停止后显示的最后一帧有明确提示。

关节和 TCP 的读取耗时都计入 read_latency_ns；增加读取内容后实际周期可能高于请求周期，按 elapsed_ns 分析。时间仍为主机接收时刻，不代表控制器内部硬件时钟或跨控制器同步时间。

## 采样区间速度统计

数字孪生通信面板现在将“实时数据”和“速度分析”分成顶层分页；选择“速度分析”后，图表拥有独立可用高度，不会被关节/TCP 表格挤出可视区域。速度分析页提供“速度统计时间段”和“计算速度”，并可点击“独立窗口查看”打开可调整大小的速度图窗口。窗口包含 TCP 线速度、TCP 角速度和 J1～J6 共 8 个独立分页，每页只绘制一个指标并使用对应单位和纵轴范围，并沿用最近一次统计结果。面板和窗口优先使用 Microsoft YaHei UI / Microsoft YaHei / Noto Sans CJK SC / SimSun，避免中文字体缺失导致字形异常。采集过程中可直接输入 `elapsed_s` 的起止值；面板会按当前连接的单调时钟范围自动更新结束时间。计算页按 TCP 线速度、TCP 角速度和 J1～J6 分成 8 个分页，每页绘制一个指标。统计文本同时显示有效相邻样本数、平均值和最大值。

速度分析提供两种方法：默认“相邻采样瞬时差分”直接计算每个采样段速度；“时间窗口平均速度”需要输入最小计算时间间隔，针对每个窗口内的全部有效采样段按实际时间覆盖进行加权平均。 速度由相邻有效采样的实际 `elapsed_ns` 差分计算。关节速度为 `abs(J[i]-J[i-1])/dt`；TCP 线速度为 XYZ 欧氏距离除以 `dt`；TCP 角速度将 FANUC WPR 转为单位四元数，以相邻姿态相对旋转的最短物理角度除以 `dt`，不使用欧拉角分量差的长度。选定区间边界按采样段实际重叠时间计入，区间内没有有效相邻样本时显示诊断信息，不会复用旧统计结果。历史缓存在当前连接内最多保留 20000 帧，停止并重新启动连接会重新建立历史。

这些值是基于本机接收时间戳的观测速度，适合对 ROBOGUIDE 当前运行过程做统计；它不替代控制器内部的速度规划或名义程序速度。工作站静止时，图中速度应接近零。

窗口平均不会把窗口末点和初点简单相减再除以时间，而是对窗口内每个采样段的关节速度、TCP XYZ 线速度和真实旋转角速度按段持续时间积分后除以有效覆盖时间；采样间隔不均匀时仍使用真实时间权重。窗口有效覆盖不足最小间隔时不会生成该窗口结果。

## 场景机器人实时跟随

通信区新增“将实时关节角映射到场景机器人”和“显示实时末端轨迹”，默认关闭。打开跟随后，最新通信关节组按自由度数匹配场景机器人，完整 J1～Jn 命名的模型按控制器轴名对应赋值，其余模型沿用 DOF 顺序：旋转关节度转弧度，直线关节mm转m，保留关节圈数。场景中须有唯一匹配机器人；无匹配或多个匹配时显示状态提示，不自动选取任意对象。对随附 `m710ic_50` 串联 URDF，确认六轴链、轴方向及零位旋转约定匹配后，转换 `模型 J3 = 控制器 J2 + 控制器 J3`，其余轴直接对应。这是 FANUC 控制器角度到该模型相对串联角的转换，不是修改原始遥测；不对其他六轴模型盲用。其他模型仍须具有对应的轴定义与零位。

末端轨迹为青色，使用映射后场景机器人当前活动工具TCP正解位置；未配置工具时使用唯一末端连杆。显示开关只隐藏曲线，跟随仍开启时继续收集轨迹。关闭跟随或停止通信后保留最后姿态与曲线，重新启动通信或替换项目清空。曲线最多保留最近20000个去重顶点，原始通信CSV照常完整记录。实时场景采用最新采样帧刷新，曲线并非控制器每个插补周期的完整轨迹。


## 2026-11-24 映射与速度计算修正

M-710iC/50 模型 `base_link` 是机械底座，`wbase` 为 FANUC 控制器 WORLD，后者在底座上方 565 mm。因此比对 TCP 要使用 `world_T_wbase.inverse() * world_T_tcp`；不能用整体平移掩盖 J2/J3 角度耦合错误，也不自动改写工程基座、工具或工件。两个独立实际姿态的场景 FK 回归在同一 WORLD/UT1 下，误差小于 0.01 mm / 0.001 deg。

速度使用控制器原始关节与直接采集的 WORLD/当前 UT TCP，不使用场景映射后的关节或 FK。J3 控制器速度与串联模型 J3 相对角速度是不同量，图表的 J3 始终表示控制器原始 J3，保留多圈差值。固定坐标原点差不会改变线速度、角速度的大小。

时段平均值按所有有效相邻段的路程/绝对关节增量/旋转角度累加后除以有效覆盖时间，不按样本数量等权平均。往返运动会累计全部路程。窗口曲线则对每个完整滑动窗口按段重叠时间积分；同一段在时段平均中仅计算一次，避免重叠窗口和不均匀采样造成偏置。最大值为当前所选方法的曲线最大值。前缀积分避免每个窗口重新遍历全部历史。

TCP 数据缺失、非有限值以及 UF/UT 切换的相邻段不产生 TCP 速度，图中留空、无有效数据时明确提示；有效关节分析继续。平均 TCP 速度仅使用有效 TCP 覆盖时间，完整窗口缺少 TCP 时该窗口留空。非单调时间戳显式报错，关节数量变化/非有限关节段被忽略，不跨坏样本补差分。

四元数采用相邻样本间的最短旋转；小于采样周期的运动细节和单步超过 180 度的转动无法从两个姿态恢复。采样时间仍为主机接收单调时钟，非控制器插补时钟。
