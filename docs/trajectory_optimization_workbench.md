# 轨迹优化工作台

## 使用流程

1. 重启本次编译后的 RobotQtViewer，在工作台列表选择“轨迹优化”。已有程序不会被强制关闭。
2. 左侧选择 tongban.STL 工件和待优化轨迹。支持示例的36道轴向扫描：TCP矩阵TXT（每点16个矩阵元素和时间，位置mm）、工艺CSV、单轨迹JSON。优先使用带喷阀与时间信息的工艺CSV；TXT仅按长轴向扫描推断喷涂区间。
3. 选择是否共享涂层分析设置。共享时，在点击优化的一刻复制当前模型、喷射/主轴方向、积分步长及所选热历史、遮挡、法向设置；以后切换涂层分析参数不会改变已完成计算的快照。独立模式使用共用的PaperGaussian参数定义、喷射+Z、主轴+Y。高斯/热历史数值常量从项目C++定义序列化，未另造一套UI常数。
4. 右侧选择“超迈管面焊接件（平面优化）”，填写允许厚度偏差百分比和目标厚度（默认165μm±10%），点击“优化轨迹”。
5. 进度条显示阶段进度；可取消。只有计算网格和额外密集/较小时间步长检查均符合指标，才标记为已接受轨迹。
6. 点击“计算优化前后厚度与均匀性并绘图”。按本次快照重新计算前后两个厚度场，显示真实STL截面、总厚度截面、同色标整板热图及统计，不使用网页旧图片。源文件改变时要求重新优化。
7. 点击“打开本次结果目录”。每次使用独立时间戳/UUID目录，不覆盖输入。

“超迈管面焊接件（全优化）”已保留独立选项，尚无独立算法，优化按钮禁用；后端也会拒绝该对象，不能误用平面算法。

## 指标与算法范围

百分比定义为 `100 × max_i |h_i / h_target − 1|`，即相对目标厚度的最大允许偏差，不是CV。另报告按表面面积加权的CV、厚度范围和指标内面积比例。仅评价外露铜片正面，管面不要求等厚；连接/隐藏区未作零厚度填充。所有数值均为模型预测。

复用网页的original_shape_v2方法：保留36道源身份、20道平板正喷、右侧至左侧的顺序和上下端关枪过渡；使用同一模型专用的局部几何方案、带上下界的轴向驻留基函数拟合、完整时序热历史反馈及扫描加速度约束。源几何/参数来源见算法目录source_manifest.json。已保存的方案仅作初值，本次始终重新计算输入基线与候选；不满足请求时会实际重新拟合速度，仍不满足则返回未达标。

模型校验限定当前tongban.STL的SHA256：`2e2a3a496f9eeb4b9918bf795a3c759b386aaa80a9396e99e0c166d738f5cc01`。导入相同模型的副本可用，其他STL必须注册自己的算法。轨迹必须匹配本方法36道源序及示例坐标：铜片Y=140mm，Z=375..575mm，管轴Z。不会把不相关轨迹静默替换为固定结果。

可达指标受保形约束与速度上下限影响，任意小的百分比不保证可行。本次真实覆盖版：165μm±10%通过；输入±5%后重新拟合仍未满足，返回未接受候选。

## 输出文件

- request.json：实际请求与涂层参数快照；inputs/和input_snapshot_request.json：本次输入副本。
- result.json：已完成计算的接受状态、前后CV/范围/偏差、密集复核、哈希及参数。
- optimized_TCP.txt、optimized_process.csv、optimized_plan.json：仅达标时使用此名称。TXT和工艺CSV必须配套，CSV保存时间及喷阀标志；TCP文本本身不携带喷阀。
- candidate_not_accepted_*：未达标时的候选，不能当成达标结果。
- thickness_before_after.csv：完整真实前后预测数据；原生对比直接根据快照重建网格并重算，不再依赖NPZ。
- thickness_comparison.png/.pdf：前后总厚度对比图；fitted_solution.json：本次拟合方案。

## 代码与运行

- 算法：SMRobotSpray/SprayTrajectoryOptimization/algorithms/chaomai_plane，无Qt UI依赖。
- UI、快照输入输出、原生后台线程、生命周期：SimWorkbench/SMRobotWorkbenchPaintingAnalysis/TrajectoryOptimizationWorkbench。
- 主窗口仅组装面板与参数快照；工作台由现有贡献注册/配置机制提供，不修改逆解或原规划算法。
- VS2019/C++17构建私有ChaomaiPlaneOptimizer对象库并静态合入工作台。模型专用初值JSON在配置时嵌入C++数据，F5及直接启动均不需要桌面网页、外部算法DLL或脚本目录。
- 产品运行不需要Python、NumPy、SciPy、trimesh或Matplotlib；解释器输入框、QProcess调用和脚本部署已移除。原脚本已备份并退出项目源码。数值层无Qt依赖，文件和PNG/PDF绘图适配使用项目已有Qt库。
- 原生数值核在自己的CMake子目录中优化编译，避免Debug的RTC与O2冲突；不改变主程序的Debug检查。
- 工作台输入/结果属于可清理的分析会话；项目释放时清除会话，已导出的独立文件保留。
